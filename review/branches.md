## Findings that change the decision

**Do not choose a production bar from the matrix's thin R windows.** Its marginal arithmetic largely holds conditional on W_D counts, but the implementation substitutes rounded ratios, starts after an unpriced first step and greedily walks a nonmonotone grid. Keeping existing auto exclusions and adding the bar-95 rule gives 227 extra inferred hand catches and 102 extra left-alone exclusions in W_D, so its first-step cost is 0.449339. Replacing the existing rule is a different experiment because some existing auto selections may fall below the new threshold.

For equal per-home values, evaluate `R * incremental_catches - incremental_over_applies` for every candidate and today's rule. On W_D, the 85-to-80 bundle costs 253/102=2.480392. Its two parts cost 99/41=2.414634 and 154/61=2.524590. The small separation is not evidence of a special optimum at 83. At the lower end, W_D's 65-to-55 bundle costs 452/72=6.277778, so the greedy rule would wrongly stop at 65 for some R values where 55 has higher total utility. Ties should be displayed as indifference, not precision about a uniquely chosen bar.

**Do not use the loss branch's $52 as a price for widening.** Even the historical all-age W_L estimate depends on an exposure denominator multiplied by the claims join. On the supplied totals, wind/hail paid A/E is 0.130091 and control paid A/E is 0.769585, giving a relative ratio of 0.169040. These are descriptive, conditional arithmetic. Illustratively, holding the reported roof ratio fixed while moving the control ratio from 0.4 to 1.2 yields relative gaps of 67.48% to 89.16%. That illustration is not a CI. Only a full policy-clustered bootstrap that also re-estimates comparator rates can supply uncertainty.

The source's latest-file dedupe is directionally right but needs two repairs. It filters missing dwelling IDs before choosing the latest claim, which can preserve an older key when the newest snapshot no longer has one. It also leaves ties within the same file unspecified. The new census tests both; these are blockers if present, not evidence that they occurred. A dwelling-only join can match more than one policy term. The executed W_E queries found zero ambiguous claim-home matches. The future guard remains: any nonzero count blocks quoting until a policy/term key is verified.

The source's exposure window includes `loss_date <= bind + exp_days` despite counting only the date difference as exposure. The proposal uses the explicit half-open interval `[start, end)` and reports its convention. Creation timestamp remains the NB cohort-entry filter, but exposure needs the agreed issue/effective start. Warehouse column comments resolve the exposure start as policy effective time and cancellation sequencing as quote effective time. The executed W_E query uses these fields, explicit America/Chicago dates, actual term end and the latest monthly claims horizon. A first-cancellation stop defines first-spell exposure; if reinstatements restore coverage, an active-interval sensitivity is needed.

**R needs a business unit.** Let B be the expected incremental value per decision-time quote of automating an exclusion an underwriter would otherwise apply: saved UW work, delay and any bind effect, with essentially no incremental coverage change if the counterfactual exclusion would happen anyway. Let C be the net expected incremental cost per decision-time quote of restricting a roof that would otherwise stay covered: bind contribution lost, expected removal/complaint/compliance cost, minus expected incremental insured-loss savings at that roof's age, score, coverage terms and persistence. Then R=B/C is usable only if C is positive and values are treated as constant across the compared band. If C is zero or negative, or values vary materially, directly compare expected utility by band. Historical dollars per excluded home-year must first be transported to marginal homes and converted using expected bind probability and covered duration; the historical loss join cannot do that conversion.
